## 2. 2026-08-16 이후 무엇이 바뀌었나

**제로베이스 재구축을 결정하고 실행했다.** 개념은 유지하고 구현을 다시 지었다.

삭제 시점의 화면 둘(`index.html` 474줄, `app.html` 757줄)은 정본에서 상수를
**손으로 옮겨 적은** 코드였다. `MIN_CELL = 20` 이 정본과 화면 양쪽에 있었고 한쪽만
고치는 날을 막기 위해 화면 리터럴을 변조하고 렌더해서 대조하는 검사를 따로 두고 있었다.

지금은 값이 한 곳에만 있다. 빌더가 빌드 시점에 정본을 읽어 화면과 계약 파일을 함께 낸다.
검사는 없어지지 않고 **경계가 옮겨졌다** — 정본을 변조하고 같은 빌더를 돌려 렌더된 화면을
확인한다.

| | 2026-08-15 | 2026-08-27 |
|---|---|---|
| 화면 | `index.html`·`app.html` (커밋된 HTML) | `screens/*.html.in` → `build/` (빌드 산출물) |
| 정본 값 전달 | 손으로 옮겨 적음 | 빌드 시점 읽기. fetch 19개 + 치환 14개 + 임직원 4개 |
| 자동 검사 | 6종 | 11종 |
| 공개 표면 | 대시보드·앱·데이터 피드 | 리다이렉트 1개 |

헌 화면 둘은 2026-08-27 에 삭제했다. 그 화면만 지키던 검사 넷(`test_single_source`,
`test_suppression`, `check_dashboard`, `shots.py`)도 함께 삭제했다.

**폐기 조건은 제안서 재현이 아니라 게이트였다.** 초안은 "새 화면이 같은 스크린샷 12장을
낼 수 있을 때" 로 정했으나, 그것은 새 UI 를 이미 발송된 PDF 에 묶는다. 조건을 게이트 넷으로
바꿨고 넷 다 닫힌 뒤에 지웠다. 발송된 제안서와 그 이미지 12장은 그대로 보존하며 재현하지
않는다.

다만 **게이트 목록이 불완전했다.** 넷을 세고 시작해서 실제로 걸린 것은 아홉이었다.
`test_suppression` 이 헌 화면 상수를 파싱했고, 촬영 스크립트가 그 화면에서 12장을 떴고,
문서 스탬프가 그 해시를 들고 있었고, 검사기 안에 97줄이 그 화면을 지키고 있었고, 발행
스크립트의 근거 문단이 "헌 화면은 로컬에서 하중을 받는다" 고 적고 있었다. 이 사실을
`REBUILD-CHARTER.md` §4.1 에 남겼다 — 목록이 틀렸다는 기록이 목록 자체보다 오래 쓰인다.

## 3. 기업 대시보드

탭 셋이 정본 `dashboard.tabs` 에서 온다. 라벨·제목·색·밴드 점유율·퍼널 분수가 전부 정본
소유이며 화면 코드에 적힌 값이 없다.

| 탭 | 무엇을 보이는가 |
|---|---|
| 개요 | KPI 카드 5개. 자격자·가입자·활성화율·반복 참여·PMPM |
| 신호 | 밴드 분포 3개(Low·Moderate·Priority)와 인원. **숫자 점수는 없다** |
| 퍼널 | 자격자→활성화→유효 촬영→발생 조치→완료 조치 5단계 |

모든 상태가 URL 이다. `?tab=` 으로 세 뷰가 각각 링크 가능하며 모르는 값은 첫 탭으로
떨어진다. 스크린샷을 스크립트로 재생성할 수 있어야 한다는 PRD 요구가 여기서 성립한다.
`?scen=`·`?dept=`·`?lens=` 는 아직 없다.

### 빌더가 거부하는 두 가지

정본이 산문으로 정하던 규칙 둘을 빌드 실패로 바꿨다.

- **퍼널은 포개져야 한다.** 뒤 단계가 앞 단계보다 크면 빌드가 죽는다. 정본
  `funnel_nesting` 이 다섯 단계가 같은 보고월과 같은 자격자 분모를 쓴다고 정하며, 그 문장의
  검사 가능한 내용이 이것이다.
- **밴드 점유율 합은 100% 여야 한다.** 안 맞으면 화면의 바 셋이 트랙을 못 채우고 그 상태는
  "나머지 사람은 어디 갔나" 에 화면이 답을 못 하는 것이다.

### 최소 셀 억제

고유 인물 20명 미만 셀은 값을 보이지 않는다. 직전 문서 시점에도 이 문구는 화면에
있었으나 재구축 초기에는 셀 자체가 없었다. 지금은 셀이 있고 규칙이 실제로 돈다.

**인원·비율·막대를 함께 감춘다.** 인원만 감추면 복원된다 — 퍼널은 자격자 분모를 같은
화면에 공표하므로, 비율과 분모를 곱하면 감춘 인원이 그대로 나온다. 구현 첫 판이 정확히 그
상태였고(`15% · withheld` 위에 자격자 100), 채움 막대의 폭도 같은 이유로 함께 지운다.
눈금 없는 막대에 위치를 표시하는 방식은 정본이 "숫자를 숨긴 숫자" 로 부르며 금지한다.

## 4. 임직원 화면

본인의 밴드와 방향 문장, 그리고 면책 문구. **숫자 점수는 보이지 않는다.** 점수는 밴드와
방향을 만들기 위해 계산되지만 렌더되지 않으며, 조건은 정본
`surfaces.employee_app.numeric_score` 가 FDA clearance 로 잡고 있다.

재구축에 넣지 않은 것: 보장률 표, 치과 목록, 잔여 한도, 예약. 정본
`status.does_not_exist` 가 넷을 대역으로 채운 것으로 분류한다. 폐기된 부스 데모의
표면이었다. 뒤에 시스템이 없는 화면을 다시 만들 이유가 없다.

### 밴드 경계를 정본으로 올렸다

직전 구현은 밴드 경계를 화면 한 줄에 두고 있었다.

```
const BAND = s => s >= 80 ? "Low" : s >= 68 ? "Moderate" : "Priority";
```

80 과 68 이 **사람에게 어느 밴드라고 말할지를 정한다.** 정본에 없었고, 읽는 검사도 없었고,
같은 밴드 이름 셋이 기업 화면의 분포를 싣고 있었다. 방향 문턱(3)과 조언 문장 셋도 같은
자리에 있었다. 전부 정본으로 옮겼고 밴드 이름 집합 셋(분포·바 색·임직원 화면)이 같아야
검사가 통과한다.

빌더가 밴드 정의의 두 모양을 거부한다. 마지막 밴드만 하한을 비울 수 있고(마지막에 하한을
주면 그 아래 점수에 밴드가 없어 화면이 그 사람에게 할 말이 없다), 경계는 내림차순이어야
한다(뒤집히면 첫 밴드가 전부를 받는다).

### 동의는 사용 시점에 평가된다

가입 시점에 정해진 플래그를 읽지 않는다. 동의는 목적별 레코드 목록이고 촬영 직전에
평가한다. 막아야 하는 상태 넷이 전부 막힌다.

| 상태 | 왜 막는가 |
|---|---|
| 철회 | 철회는 사건이며 기록을 지우지 않는다. "처리한 날 우리는 무엇을 허락받았나" 에 답할 수 있어야 한다 |
| 미부여 | — |
| 대체된 정책 문안에 부여 | **boolean 으로 표현할 수 없는 상태.** 동의했으나 우리가 이미 바꾼 문안에 동의했다 |
| 사진은 현행, 처리 근거는 철회 | 한 목적만 보는 검사가 통과시키는 조합 |

차단된 사람에게는 밴드도 보이지 않는다. 보이면 하지 말라고 한 처리의 결과를 화면에 놓는
것이다.

## 5. 검증 체계

`make check` 와 CI 가 같은 검사 11개를 돌린다. 개수와 집합을 검사기가 직접 대조하므로 세
곳이 다른 숫자를 말하는 상태가 되지 않는다.

| 검사 | 무엇을 보는가 |
|---|---|
| `check-forbidden-terms.sh` | 레드라인 단어와 금지 신호 라벨. 선언한 경로가 없으면 **건너뛰지 않고 실패한다** |
| `check-package-consistency.py` | 정본↔문서↔저장소 규칙. 바 대비 3:1, 임직원 문구 11개, 착수 게이트, 발행 경계 |
| `test_doc_freshness.py` | PDF 5종이 원본 md 와 일치하는지 |
| `test_build_reads_canon.py` | **정본 변조 → 빌더 → HTTP → Chrome DOM.** 단언 152건 |
| `test_consent.py` | 동의 평가와 데이터 경계. 단언 16건 |
| `test_tech_sql.py` | 기술문서 SQL 의 테이블·컬럼 실재 |
| `test_export_contract*.py` | A3 export 계약 (지금은 SKIP, phase 전환 시 필수) |
| `test_fixtures.py` | fixture 산술 재확인 |
| `test_pages_root.py` | 발행 루트가 리다이렉트인지 |
| `generate_synthetic.py --check` | 297만 행 생성기의 파생·결정성 |

### 이 체계가 이렇게 생긴 이유

검사가 **통과하면서 아무것도 안 보는** 상태를 여러 번 만들었다. 렌더가 실패해 빈 문서가
나왔을 때 "위반 없음" 으로 읽은 적이 있고, 세는 변수를 두고 출력에는 계산된 상수를 찍은
적이 있다. 그래서 지금은 두 규칙을 지킨다.

- **검사를 커밋하기 전에 그 검사가 실패하는 것을 실제로 본다.** 고장을 심고 확인한다.
  이 문서가 다루는 구간(PR 6건)에서 재현한 고장은 55건이다.
- **범위를 검사가 스스로 강제한다.** 계약에 스테이징된 키나 템플릿의 치환 자리에 변조
  케이스가 없으면 검사가 실패한다. 계약이 커질 때 검사가 조용히 뒤처지지 않는다.

### 옮긴 커버리지와 잃은 커버리지

`test_suppression` 을 삭제하면서 그 단언을 빌드 경계로 옮겼다. 실제 시나리오 셋과 셀 탭
둘, 6개 상태에서 화면에 뜬 인원 15개가 전부 문턱 위임을 확인한다. 최소 셀 검사와 방향이
반대이며 둘 다 필요하다 — 앞엣것만 있으면 언제나 감추는 화면이 통과하고, 뒤엣것만 있으면
절대 안 감추는 화면이 통과한다.

**잃은 것은 부서 차원이다.** 헌 검사는 시나리오 3 × 부서 3 × 탭 6 = 54 상태를 걸었고 새
화면에는 부서 필터가 없다. 데모 정본에 부서 데이터가 없기 때문이며, 그 필터의 목적이 억제를
화면으로 끌어내는 것이므로 합성 기업 하나를 잘라 비슷하게 만들어도 보여주는 것이 없다.
`?dept=` 가 돌아올 때 함께 돌아온다.
