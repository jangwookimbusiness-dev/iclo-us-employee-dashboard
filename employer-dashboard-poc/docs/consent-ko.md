# 부스 촬영 동의문 (초안) — SWT Seoul 2026-08-27

> **보류. 이 문서는 더 이상 필요하지 않습니다.** 2026-08-12 결정으로 부스 라이브 캡처가 폐기됐고,
> 부스에서는 개인정보를 전혀 처리하지 않습니다. PIPA §23 별도 동의도 적용되지 않습니다 (PRD §5.7).
>
> 지우지 않고 남기는 이유는 분석 자체가 재사용되기 때문입니다. 다만 **미국 PoC 에는 그대로 못 씁니다.**
> 관할이 PIPA 가 아니라 HIPAA 와 주법이고, 부스 방문자가 아니라 임직원과 피부양 가족이 대상이며,
> 동의 이전 기준선 적재 문제(`start_gates.baseline_before_consent`)가 따로 있습니다.

> **D1 · 마감 8/12 · 법률 검토 필요.** 이 문안이 확정되기 전에는 촬영 관련 구현(D3·D4)을 시작하지 않는다 (PRD §3.3 WS0).
> 근거: 개인정보 보호법(PIPA) §15①, §22, §23, §28-8.
>
> **§23이 이 문서의 형태를 결정한다.** 구강 이미지는 민감정보(건강정보)이므로 동의를 **다른 동의와 분리해서** 받아야 한다.
> 그래서 화면이 셋이다 — 촬영 동의(필수)와 연락처 동의(선택)는 같은 화면에 두지 않고, 하나의 체크박스로 묶지 않는다.

## 설계 전제 — 문안보다 먼저 지켜야 하는 것

| 항목 | 처리 |
|---|---|
| 구강 이미지 | **저장하지 않음.** 분석 호출 후 즉시 폐기. 서버·로그·브라우저 캐시 어디에도 남기지 않음 |
| 명찰 QR | 읽는 즉시 일방향 해시. 평문과 거기서 해독된 항목(이름·회사·직함·연락처)은 저장하지 않음 |
| 명찰 해시 | **행사 당일 종료 시 파기.** 중복 촬영 확인이 목적이고 그날로 끝남 |
| 신호 등급·촬영 시각 | 해시 파기 시 시각을 시간 단위로 뭉갬 → 남는 기록은 특정 개인과 연결되지 않음 |
| 연락처 | 별도 동의, 별도 테이블, **날짜까지만** 기록. 촬영 기록과 연결 키 없음 |
| 저장 위치 | **국내 리전.** Supabase 프로젝트를 서울(ap-northeast-2)에 만든다 — 국외 이전(§28-8)이 성립하지 않게 |

> **국외 이전은 리전 선택으로 피한다.** 프로젝트를 해외 리전에 만들면 §28-8에 따라 이전 국가·목적·항목·보유기간을 고지하고
> **또 한 번 별도 동의**를 받아야 한다. 동의 화면이 하나 더 늘고 이탈률이 오른다. 서울 리전을 쓰면 이 조항 자체가 안 걸린다.

## 화면 1 — 구강 이미지 처리 동의 (필수)

> 이 화면에는 이 동의만 둔다. 연락처·마케팅·약관을 같이 올리지 않는다.

### ICLO 부스 시연 · 민감정보 처리 동의

ICLO는 이 부스에서 구강 사진으로 구강 상태 신호 등급을 산출하는 과정을 시연합니다.
구강 사진은 개인정보 보호법상 **민감정보(건강에 관한 정보)**에 해당하여, 아래 내용을 확인하고 동의하신 경우에만 진행합니다.

**1. 처리 목적**
부스 시연입니다. 촬영한 구강 사진에서 신호 등급을 산출하여 본인에게 보여드리고, 개인을 알아볼 수 없는 집계 형태로 부스 화면에 반영합니다.
**진단이 아니며 의료적 판단에 사용할 수 없습니다.**

**2. 처리 항목**

| 항목 | 저장 여부 |
|---|---|
| 구강 사진 | **저장하지 않습니다.** 분석 직후 즉시 삭제되며 서버에 기록되지 않습니다 |
| 신호 등급 (LOW / MODERATE / PRIORITY) | 저장합니다 |
| 촬영 시각, 분석 모델 버전 | 저장합니다 |
| 명찰 QR | 읽는 즉시 복원 불가능한 값으로 변환하여 저장합니다. **이름·회사·연락처는 저장하지 않습니다** |

**3. 부스 화면에 무엇이 올라가는지**

| 화면에 올라가는 것 | 어떻게 | 언제 |
|---|---|---|
| 촬영 건수 | "오늘 촬영 N건"의 숫자가 1 올라갑니다 | 촬영 직후 |
| 신호 분포 막대 | 귀하의 등급에 해당하는 막대에 **한 명분이 더해집니다.** 누구인지는 표시되지 않습니다 | 촬영이 5건 모인 뒤 |

**촬영 직후에 분포를 바꾸지 않는 이유**가 있습니다. 촬영하자마자 막대가 움직이면, 화면을 보고 있던 사람이 방금 촬영하신 분의 등급을 알게 됩니다. 그래서 5건씩 묶어서 반영합니다. 20명 미만인 항목은 값 대신 “표시할 수 없음”으로 나옵니다.

| 화면에 올라가지 않는 것 |
|---|
| 구강 사진 — 저장 자체를 하지 않습니다 |
| 이름·회사·연락처 |
| 촬영 시각 — 기록은 하지만 화면에 표시하지 않습니다 |
| 개인의 등급을 개인과 함께 보여주는 화면 — **그런 화면이 없습니다** |

**4. 화면을 채우는 나머지는 가상 정보입니다**

부스 화면은 미국 기업 고객용 대시보드입니다. 원래는 회사가 제공하는 재직·보험 자격 정보가 있어야 화면이 완성되는데, 이 자리에서는 그런 정보를 받지 않습니다. 그래서 **부서·근속·진료 청구 같은 항목은 무작위로 만든 가상값**을 채워 넣습니다.

귀하에게서 온 것은 **신호 등급 하나뿐**입니다. 화면에서도 어느 숫자가 실제 촬영에서 왔고 어느 숫자가 가상인지 항목마다 표시됩니다.

**5. 보유 및 이용 기간**
명찰에서 변환된 값은 **행사 당일 종료 시 파기**합니다. 파기 후 남는 기록(신호 등급·시각)은 특정 개인과 연결되지 않으며, 시연 통계 목적으로만 이용합니다.

**6. 동의를 거부할 권리**
동의하지 않으실 수 있습니다. **거부하셔도 부스 관람과 제품 설명에는 아무런 제한이 없습니다.** 촬영이 진행되지 않을 뿐입니다.

**7. 참여 전 확인 사항**
- **본인의 결과는 본인 휴대폰에만 표시됩니다.**
- 만 14세 미만은 법정대리인 동의가 필요하여 참여하실 수 없습니다.

## 법률 검토 시 확인받을 것

1. 구강 사진을 저장하지 않아도 **처리 시점에 민감정보 처리로 보아 §23 별도 동의**가 필요하다는 해석이 맞는지 (본 문안은 필요하다고 보고 작성)
2. 명찰 QR 해시가 **가명정보인지 익명정보인지** — 가명정보면 §28-2 이하가 적용되고 결합·안전조치 의무가 추가됨
3. 당일 해시 파기 + 시각 뭉개기 후 남는 기록을 **익명정보로 볼 수 있는지**
4. 부스 현장에서 **전자적 동의(체크박스 + 버튼)**로 §22 형식 요건이 충족되는지, 서면이 필요한지
5. Core AI가 ICLO 자체 시스템이면 처리위탁 고지 불필요 — **외부 사업자면 §26 위탁 고지가 추가**되어야 하므로 확인 필요
6. 개인정보 처리방침 게시 의무 — 부스 QR에서 접근 가능한 링크로 충분한지
7. 실제 촬영 기록에 **가상 항목(부서·근속·청구)을 결합**해 표시하는 것이 고지 대상인지 — 본 문안은 개인정보는 아니지만 오인 소지가 있다고 보아 §4에 명시
