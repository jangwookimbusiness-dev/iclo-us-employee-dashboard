# 제안서 v11 공동 브리프

v1(Claude 주도 · Codex 검토)과 v2(Codex 주도 · Claude 검토)는 **이 문서 하나에 똑같이 묶인다.**
두 판을 비교하려면 제약이 같아야 한다. 구성과 문장은 각자 백지에서 만든다.

---

## 1. 누가 읽는가

**Snowflake Korea 비기술 임원.**

이 사람이 아는 것과 모르는 것을 정확히 갈라야 글이 산다.

| 안다 | 모른다 |
|---|---|
| Snowflake 제품과 거버넌스 기능 | 미국 치아보험이 어떻게 굴러가는지 |
| 데이터 플랫폼 영업이 어떻게 도는지 | self-funded / fully insured 차이 |
| 스타트업 지원 프로그램의 작동 방식 | TPA·ASO·stop-loss가 각각 뭔지 |
| 한국 기업의 복리후생 관행 | 미국 임직원 복리후생 제도 |
| — | X12 834·837D·835가 뭔지 |

**따라서:** Snowflake 기능은 설명하지 않는다. 보험은 처음부터 설명한다.
한국 독자가 아는 것(실손보험, 건강검진, 4대보험)에 빗대되, **빗댄 다음에는 반드시 차이를 밝힌다.**
비유만 남기고 차이를 안 밝히면 나중에 잘못된 전제로 의사결정한다.

## 2. 무엇을 요청하는가

v10과 동일하다. **Step 0 — 현재 한국 스타트업 담당이 미국 HLS GTM·아키텍처 담당자를 지정하고 연결한다.**

이 문서는 투자 제안이 아니고 제품 판매도 아니다. **라우팅 요청**이다.
읽는 사람이 "그래서 내가 뭘 하면 되나"에 30초 안에 답할 수 있어야 한다.

## 3. 사실 기반

`contracts/proposal-package-v11.yml`이 정본이다. 수치를 새로 만들지 않는다.

- 수치·라벨: `dashboard.*` (합성 데모 값임을 반드시 표기)
- 하면 안 되는 주장: `scoped_claims`
- 금지 용어: `terminology.forbidden` · `disease_words_banned`
- 출처: `output/proposal-v10/04_QA/Sources-v10.md`
- 출처 없는 주장 목록: 같은 파일 마지막 절. **이 목록에 있는 것은 단정하지 않는다.**

### 반드시 노출 (`required_disclosure.proposal_ko`)

두 가지가 빠지면 다 만들어진 제품처럼 읽힌다. 빠뜨리면 검사기가 잡는다.

**`status`** — 오늘 도는 것은 합성 대시보드 하나뿐. 임직원 웹앱·Core AI 호출 경로·급여 게이트웨이는 **존재하지 않는다.**
**`start_gates`** — HIPAA 역할 규정 · 데이터 권리 · 동의 이전 기준선 적재 · 공통 식별키. 넷 다 열려 있고, 실데이터 적재 전에 서면으로 닫아야 한다.

## 5. 문체 규칙

### hallmark `copy.md`

- 구체적 명사·동사. 감정 약속 금지 — "혁신적", "강력한", "원활한" 류는 쓰지 않는다
- 능동태
- 용어는 하나만 골라 끝까지 쓴다
- 금지 오프닝: "오늘날 급변하는", "~의 새로운 패러다임", "A와 B의 만남"
- 타이포그래피: `…`(U+2026), 굽은 따옴표, 범위는 `–`

### killaislop.com — 이 문서에 걸리는 것

35개 tell 중 텍스트·문서에 해당하는 것만:

- 문단 안에 키워드 하이라이트 흩뿌리기
- `not just X — it's Y` 류 공식 문장
- 제목·불릿마다 이모지
- **지어낸 통계 3개 나열** — 특히 이것. 수치는 contracts에 있는 것만
- 장식용 `01 / 02 / 03` 섹션 번호
- 모든 제목 위 소문자 대문자 kicker 라벨
- 서로 바꿔 껴도 되는 카드 그리드

6원칙 중 이 문서에 직접 걸리는 것: **Subtract first**(먼저 덜어낸다), **Specific beats loud**(구체가 크게 말하기를 이긴다), **Decoration must mean something**.

### em-dash

산문 한복판 appositive dash를 쓰지 않는다. 표·목록·제목의 구분자는 허용.
`X — Y` 대신 `X. Y` / `X, Y` / `X: Y` / `X(Y)`.

## 5.1 데크에 걸리는 hallmark 게이트

hallmark `slop-test.md`는 게이트가 57개인데 대부분 HTML/CSS 전용이다(`focus-visible`, `prefers-reduced-motion`, `grid-template-columns`, OKLCH 토큰). 슬라이드에 옮겨오는 것만 남긴다.

| 게이트 | 원문 | 데크에서 뜻하는 것 |
|---:|---|---|
| 3·4·5 | 3열 아이콘 카드 그리드 / 카드 안 카드 / 굵은 좌측 컬러 보더 | 서로 바꿔 껴도 되는 카드 3개를 나열하지 않는다. 카드 안에 카드를 넣지 않는다 |
| 6 | 히어로가 전부 가운데 정렬 | 표지에서 제목·부제·요청을 한 축에 다 세우지 않는다. 최대 둘만 가운데 두고 나머지는 축을 깬다 |
| 8·9 | 일반 AI 템플릿 구조 재사용 / 절마다 같은 리듬 | 슬라이드마다 같은 레이아웃을 반복하지 않는다. 표·본문·도식이 번갈아 나와야 한다 |
| 21·32 | 기본 매크로구조로 흘러가기 | 16장이 전부 "제목 + 불릿 3개"면 실패다 |
| 37·38 | 폰트 3종 초과 / outlier 3슬롯 이상 | 서체는 본문·제목 둘, 예외 하나까지 |
| 40·41 | 대비 임계값 | 본문 4.5:1, 큰 글씨·아이콘 3:1. Coral `#C2333A`는 흰 배경 5.49:1로 검증됨 |
| 44 | 콘텐츠가 폴드 안에 | 한 장에 들어가는 분량만 넣는다. 넘치면 장을 쪼갠다 |
| 45 | 의미 없는 장식 | 근거 없는 아이콘·배지·번호를 넣지 않는다 |
| **46** | **지어낸 수치** | contracts에 없는 숫자는 쓰지 않는다. 3절과 같은 규칙 |
| **47** | **가짜 UI 크롬 그리기** | 대시보드를 도형으로 흉내내지 말고 실제 스크린샷을 쓴다 |
| **54** | **eyebrow 옆 제목 (tag-left, header-right)** | **자동 실패.** v10 덱 16장이 전부 `확정된 ICLO 방향 / PoC 범위` + `ICLO 내부 검토 자료` + `04`를 제목 옆에 단다. 그대로 베끼지 않는다. 라벨이 필요하면 제목 **위 같은 열**에 세로로 쌓는다 |
| 55 | 대문자 제목 line-height < 1.0 | 두 줄로 넘어갈 때 글자가 겹친다. 1.02 이상 |

게이트 54는 "기존 판과 구조를 맞춰라"는 지시로도 우회되지 않는다고 hallmark가 명시한다. 참조본이 규칙보다 오래됐으면 규칙이 이긴다.

## 5.2 이미지에 대한 hallmark의 입장

`imagery-kit.md`는 생성 이미지를 분위기·질감·장식에만 쓰라고 하고, 실제 피사체가 필요하면 진짜 스톡 사진을 쓰라고 한다.

> **Don't use kit imagery as the literal subject.** … those need photographic placeholders (Picsum / Unsplash).

6절의 생성 방침은 이 권고와 어긋난다. 사용자 지시가 codex 생성이므로 생성을 쓰되, **이 충돌을 알고 쓰는 것**과 모르고 쓰는 것은 다르다. 생성본을 쓰는 이유는 피사체를 정확히 통제할 수 있어서다(미국 치과 + 카드 전달 + 텍스트 없음). 그 통제가 필요 없는 자리라면 스톡을 쓰는 편이 낫다.

## 6. 이미지 규칙

codex 내장 `image_gen.imagegen`으로 생성한다. 검증됨: 1536×1024 PNG, 1장당 약 2분.

**넣는 것** — 비전문가가 글로는 못 잡는 물건. 정보를 나른다.

- 미국 치과 접수 창구에서 보험카드를 내는 장면
- EOB(급여 명세서) 같은 실제 서류가 어떻게 생겼는지
- 자격 파일이 오가는 경로의 물리적 실체

**넣지 않는 것** — 무드 사진. 웃는 회의실, 악수, 상승 그래프를 바라보는 사람.
이건 killaislop 원칙 6번 위반이고, 안티슬롭 문서에 넣으면 자기모순이다.

**생성 규칙:** 텍스트·로고·워터마크 없음. 인물은 손이 보이면 반드시 검수(AI 최대 취약점).
브랜드색과 충돌하지 않게 채도 낮게. 생성 후 사람이 눈으로 보고 통과시킨 것만 쓴다.

**표기:** 생성 이미지에는 캡션에 그 사실을 밝힌다. 실제 고객 사진으로 오인되면 안 된다.

## 7. 두 판의 진행

| | 주도 | 검토 |
|---|---|---|
| v1 | Claude | Codex |
| v2 | Codex | Claude |

검토자는 **주도자의 초안을 보지 않은 상태에서 브리프만 읽고** 자기 판을 만든다.
그래야 두 판이 서로 오염되지 않는다.

검토는 다음 넷을 본다.

1. 4절 필수 노출이 실제로 들어갔는가 (status · start_gates)
2. 3절 사실 기반을 벗어난 수치·주장이 있는가
3. 5절 문체 규칙 위반
4. 비전문가가 읽고 "그래서 뭘 하면 되나"에 답할 수 있는가
